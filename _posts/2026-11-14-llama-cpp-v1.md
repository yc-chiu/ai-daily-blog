在自己電腦上跑開源語言模型，早就不是新鮮事，依 ggml-org 團隊的說法，llama.cpp 讓多模態大型語言模型能在「從消費級本機到高階企業伺服器」（"from consumer-grade local machines to high-end enterprise servers"）的各種硬體上執行。依 GitHub API，這個 repo 建立於 2023 年 3 月 10 日（UTC），採 MIT 授權。2026 年 11 月 13 日，ggml-org 團隊在 GitHub 推出 v1.0.0，並在 Hugging Face 部落格發文說明。這次的重點不是「終於能在本機跑模型」，而是專案來到 v1.0.0，以及團隊表示往後會用主版本號標示不相容改動。

## 團隊表示，三年半的累積讓穩定 API 變得必要

Hugging Face 部落格文章由 Daniel Bevenius、Georgi Gerganov 與 merve 署名。文中寫道，專案自誕生以來的「3.5 年」（"3.5 years since its inception"）成長很多，已有許多下游應用依賴他們的成果；每多一個整合，就有更多開發者依賴函式庫介面，因此「一個彈性但穩定的 API 至關重要」（"having a flexible but stable API is paramount"）。

這次一起來到 v1.0.0 的有兩個函式庫：負責推論的 llama.cpp，以及底層的機器學習張量函式庫 ggml。團隊宣稱，往後兩者都會「以主版本號的提升反映 API 與 ABI 的不相容」（"will reflect API and ABI incompatibilities with major-version bumps"）。API 是程式呼叫函式庫的規格，ABI 則是編譯好的程式能否直接接上新版函式庫的規格。

## ggml-org 團隊公布的版本規則，讓下游知道升級風險有多大

依部落格文章，所有採用語意化版本（semantic versioning）的 ggml-org 專案都適用以下規則：

| 版本號 | 什麼情況會升 |
| --- | --- |
| MAJOR（主版本） | 公開 C API 出現破壞性改動 |
| MINOR（次版本） | 向下相容的新功能、後端更新、模型支援或新增 API |
| PATCH（修補版） | 修 bug，不改 API |

<!-- 表格來源行：Hugging Face Blog〈llama.cpp v1.0.0 : A stronger foundation for the local AI ecosystem〉，Semantic version update rules，ggml-org 團隊公布。 -->

依 Release 說明，v1.0.0 本身就做了一次大掃除：移除 35 個已棄用的函式，並把原本放在 `llama-ext.h` 的 NextN API 正式納入 `llama.h`。同一版也加入 FP8 KV 快取、新的模型架構與多項 `llama-server` 安全修正，例如 SSRF、CORS 與 DNS rebinding 相關問題。

團隊也宣稱，目前 llama.cpp 支援「超過 150 種架構變體」（"more than 150 architecture variants"），以及所有主流的推測解碼（speculative decoding）方法。以上數字與承諾皆為團隊宣稱，本站未另行驗證。

## 團隊宣稱會擴大發行管道，並維持對程式碼的掌控

部落格列出的取得管道包含 Docker、Debian、Homebrew、conda-forge、MacPorts、Winget 與 XCFramework，涵蓋 Linux、macOS、Windows、Android 與 iOS 的預先發布版本。團隊也提到，會在開發流程中「審慎、合理地」（"thoughtful and resonable"）整合大型語言模型，同時把維持高品質程式碼、「掌握架構」（"staying in control of the architecture"）與理解實作細節列為最優先；測試硬體則有 NVIDIA、AMD、Qualcomm、Arm、IBM 與 Intel 支援。

## 對在本機跑模型的人來說，v1 的意義在於可以預期

本站認為，v1.0.0 對一般使用者的直接影響不大，模型照樣能跑；真正受益的是把 llama.cpp 包進自己 App、伺服器或工具裡的開發者。以前每次更新都可能要檢查介面有沒有變，往後只要看主版本號有沒有跳，就能大致判斷升級要花多少力氣。對重視隱私、想讓 AI 留在自己機器上的團隊，這也讓本機方案更容易長期維護。本站之前整理過 [Sam Altman 認為本機推論讓 DRAM 多半閒置、應在雲端追求最大使用率]({{ site.baseurl }}{% post_url 2026-11-01-sam-altman-cheeky-pint %}) 的說法；雲端與本機各有支持者，而 llama.cpp 團隊在文中則預期，隨著「本機 AI 與隱私」（"local AI and privacy"）越來越重要，依賴他們成果的應用還會持續增加。

本站建議：已經直接呼叫 `llama.h` 的開發者，升級前先對照 Release 說明的 API changes，確認用到的函式不在這次被移除的清單裡；只透過其他上層工具間接使用的人，留意該工具何時跟進即可。
